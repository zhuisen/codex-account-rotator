## 4. 验证口径（比"编译过"高的闸）

- **先跑不变量守卫**：`python3 -m unittest discover -s tests -p 'test_*.py' -v`（**519 条 / 47 个文件**，覆盖锁序、已退役 SwiftBar 入口、额度窗口与 `limit_id` 身份、「不许编造满额」、agy 模型名归一、增量解析、缓存签名、主题对比度、菜单栏宽度、图例分区…）。
  ★ **「一律不 import」这条已细化**：绝不读真实 `auth/`/`state.json`、绝不刷 token、绝不发计费请求 —— 这三条不变。但**按路径 import 是允许的**，前提两条同时成立：① 目标模块顶层只有常量（`proxy.py` / `codex-rotate` 已核，服务器启动在 `__main__` 下）；② **每一条写盘路径都打桩**（`test_quota_never_fabricated.py` 把 `_mutate_state` 换成对夹具 dict 的操作 —— 真实现会写真的 `state.json`）。行为测试比纯文本断言强得多，但这两个前提缺一不可。
- **验健康用只读 `codex-rotate health`，绝不用 `refresh`**——`refresh` 轮换 refresh_token，本身有破坏性。本地 JWT `exp` 查不出服务端 revoke（见 B21）。
- **UI 改动必须看像素**，tsc/cargo 绿不代表画对。**已固化为 `codexbar/uishot/make_harness.py`**（2026-08-11，此前一直是一次性脚本）：`npx vite build --outDir uishot/app` → 生成 `harness.html` / `harness-menubar.html`（注入 `__TAURI_INTERNALS__` 打桩后加载**同一份 bundle**）→ 经 `devport` 起静态服务 → Chrome `--headless=new --screenshot`。参数：`?nav=home|traffic|settings|platform:<k>&mode=full|noRead|none&w=412&hover=1&plat=demo&tab=today&click=文本~序号&mm=<0..100>`（`tab=today` 直开菜单栏今日 Tab）。快照可用 `CODEXBAR_SNAPSHOT=<path>` 覆盖，专用来渲染**退化态**（只有 1 个小时桶 / 空数据）—— 真快照是 app 正在写的活文件，只读不改。
  - ⚠️ **页面有入场动效之后，截图必须晚于 ~1s**（`.cb-wipe` .7s + `useIntro` 看门狗 950ms），否则截到数字滚动的中途值。`__PROBE__` 自己 2.2s 才发，探针不用额外等 —— 要控时的只有截图。
  - 验「悬浮才出现的读数」用 `?mm=<0..99>`：它对命中带真派发 `mouseenter`/`mousemove`，验的是 **React 事件处理**不是 CSS 伪类（headless 下 JS MouseEvent **不会**激活 `:hover`），报告时把两者分开说。
  - ★ **`click` 的命中数必须核到唯一**：探针出的 `clicks` 会报「命中 N 个 / 点了第几个」——**点错位置和没点中长得一模一样**，不核就是假绿（同全局那条「反向验证的变异点必须唯一」）。匹配规则与另外两个坑（只取最内层节点、序号分隔符不能用 `#`）写在 `make_harness.py` 的注释里，不在这儿复制。交互后才出现的表单态读 `inputs` 探针。
  - ⚠️ **产物目录不能叫 `dist`**：本机对 `dist/` 有读取限制，Read 与 Bash 都不可达，所以静态服务器读不到它。叫 `uishot/app` 才能跑。
  - ⚠️ **Chrome 最小窗口宽 500**：传 `--window-size=352` 会按 500 布局却按 352 裁图，伪装成"横向溢出"。菜单栏要开 520 窗口 + `?w=352` 用 CSS 把文档钉宽，量 `root.scrollWidth` 才能排除。
  - 数据用**真实形状**而不是设计稿假数据——上次正是真数据才暴露出徽章变长把日期挤断行。但 `read_state` 必须喂**脱敏夹具**（邮箱/姓名/account_id 全替换，`active` 要跟着重映射否则"当前号"判错）：真 `state.json` 能认人，**绝不放进 HTTP 伺服目录**。流量快照无凭证，**内联**进 HTML 而不是 fetch（fetch 是异步的，app 挂载时就调 `read_traffic_snapshot`，竞态会让首屏画成空）。
  - ★★ **必须在 harness 里捕获 `error` / `unhandledrejection` 并连同「已挂载节点数」一起报**。2026-08-11 连中两次同一类**假阴性**：页面因为打桩缺口零渲染，而**零渲染的页面量出来正好是"零溢出、零报错"，看着像通过**。两个缺口都记在这里，加平台/改组件时照抄：`metadata` 不能是空对象（`getCurrentWindow()` 直接取 `metadata.currentWindow.label`）；`read_auth_tokens` 不能返回 null（`slotToAccount` 会直接索引 `tokens[aid]`）；`unlisten` 走的是**另一个全局** `__TAURI_EVENT_PLUGIN_INTERNALS__.unregisterListener`。

### 7.-1 ★★★ 仪器自己会撒谎 —— 动手前的六问（2026-09-10 汇总）

**这一节是本仓最贵的一条经验的总纲。** 2026-09-10 一天之内我犯了 17 次错，
其中 **15 次是同一个形状：我的测量工具坏了，而坏掉的样子长得像「通过」。**
判断失误只有 2 次。所以真正要防的不是"想错了"，是**"量错了却以为量对了"**。

#### 六问（跑任何验证之前逐条回答，不许跳）

| # | 问 | 本轮的真实翻车 |
|---|---|---|
| ① | **这个探针在已知阳性上响过吗？** | 用 zsh `source` 了 bash 脚本（zsh 数组 **1-indexed**，`${argv[0]}` 恒空）⇒ 得出「`app-server` 会注入 profile」，与事实相反 |
| ② | **选择器/参数真的命中了吗？** | `-k world_readable` 对 `WorldReadable` **大小写不匹配**，选中 0 条；URL 里重复的 `relay=` 被 `URLSearchParams.get` 取第一个，稀疏夹具**从未生效** |
| ③ | **断言打在被测的那个东西上吗？** | 走势线正则 `<path d="M...">` 命中了**侧栏图标**，「7 个点」被读成 1；`assertNotIn("全部")` 与「全部站」子串撞车 |
| ④ | **我把失败输出静音了吗？** | `>/dev/null 2>&1` 吞掉构建守卫的警告 ⇒ 用旧 bundle 渲染并测了两轮；`npm run build \| grep "error TS"` 吞掉 vite 的失败 |
| ⑤ | **这个「红」是被测的那条断言给的吗？** | 变异改回 `exit 78` 撞上 `assertNotIn` 而红，但把整句后果**删掉**照样绿 —— 同一个测试里另一条断言是空的 |
| ⑥ | **基线是绿的吗？还原后复跑了吗？** | 见 `tools/mutate.py` 的表格 |

#### ★ 工具化的那一半：`tools/mutate.py`

⑤⑥ 与「锚点不存在/出现多次/文件没变」已经**做成工具**，因为它们是流程漏项不是判断失误 ——
流程漏项要用工具挡。手写变异脚本一律改用它：

```python
import sys; sys.path.insert(0, "tools")
from mutate import Mutator
m = Mutator("tests/test_x.py")
m.baseline("MyClass")                                    # 基线绿 + 选中数 > 0，否则中止
m.mutate("src/a.ts", old, new, "MyClass", expect="red",   why="退回旧实现")
m.mutate("src/a.ts", o2,  n2,  "MyClass", expect="green", why="良性换序（防假红）")
m.done("MyClass")                                        # 还原 + 复跑
```

任何一项不过就 `SystemExit` —— **不许跑出一份看着完整的报告**。

#### 剩下那一半只能靠纪律，但可以缩成三句话

1. **每一条 assert 都要有属于它自己的变异**，且方向要包含「**把被断言的东西整个删掉**」——
   只做「改成错的」会漏掉「根本不存在也通过」，而后者才是真实的退化方式。
2. **断言前剥掉所有形式的注释**：python `#`（含**行尾**）、docstring、JSX `{/* */}`、shell `#`。
   本轮有 3 条闸被自己的说明文字判绿/判红。
3. **定长切片取上下文是危险的**（`PY[i:][:600]` 会滑进下一段代码/注释）。
   要么解析到结构边界，要么**直接调用函数拿返回值** —— 后者一次就把两个方向的变异都点红了。

#### ⑦ 判据档位要挑「只有被测那条能挡住」的输入

多条 early-return 串在一条路径上时，随手挑一档会被上游那条兜住。
实测：验「上一窗口必须整段可观测」时挑了 30d，而它的「—」是 `if (!before) return null` 给的，
**根本没走到被测的守卫**；真正的分界档是 14d（上期部分重叠）。
★ 每次问：**这条断言的绿，是谁给的？**


### 7.0 反复踩过的「假绿」形态（从 memory.md 现况板迁来 —— 那是教训不是进行时）

- **块注释里写带 `**` 的 glob 会把注释截断**：`~/.grok/**/updates.jsonl` 里的 `*/` 就是块注释结束符。
  报错点出现在十几行之外（TS1127/TS1160），完全看不出真因。查法：数全文 `/*` 与 `*/` 的配对。
- **`npx tsc` 在项目外会拉到一个同名恶作剧包**（输出 "This is not the tsc command you are looking for"，
  且**退出码为 0**），三个最小复现全部"通过"——假绿。隔离验证 TS 一律用 `<repo>/node_modules/.bin/tsc`。
- **`vite build --outDir uishot/app` 会清空 outDir**，把 `harness.html` 一并删掉。顺序必须是
  先 `vite build` 再 `make_harness.py`；反过来 404，而 404 截图看着就像"页面没渲染"。
- **变异测试脚本必须核「文件真的变了」再判绿红**。perl 转义失败导致变异没打上，
  脚本却报成「守卫是假的」—— 「替换没匹配＝假『已改好』」的翻版。
- ★★ **空守卫的六种形态**（本轮变异测试一次抓出六个，全是我自己写的）：
  ① 子串存在 ≠ 规则存在（`::-webkit-scrollbar` 在 `-track`/`-thumb` 里也含）；
  ② 名字出现过 ≠ 真的接上了（`const glow` 还在但没传给 `<Ring>`；`grokReasonTone` 还在 import 行）；
  ③ 同文件同名属性 ≠ 同一个元素（`flexShrink:0` 另一处是 spinner）；
  ④ 断言打在**含注释的原文**上（注释里正解释着这条规则，永远匹配得到）；
  ⑤ 大小写敏感漏匹配（断言 `Rem`，变量是 `rem`）；
  ⑥ 拿**不成立的前提**去验（用停用 kimi 的夹具验"停用 grok"）。
- ★★ **空守卫第七、八种形态（2026-09-10 各抓一个，都是我自己写的）**：
  ⑦ **闸根本没被收集**。pytest 风格的**普通类**（不继承 `unittest.TestCase`）必须
     `Test*` 开头，否则整个类静默跳过。判据：加了 N 条用例，**总数没变** ——
     `tests/test_proxy_relay_upstream.py` 里加两条、总数纹丝不动仍是 20。
     （本仓多数测试是 `unittest.TestCase` 子类，pytest 无视命名照收，所以这个坑只在
     pytest 风格的文件里显形。）
  ⑧ **断言打在会被夹具覆盖的地方**。判「缓存写入是否原子」时我断言
     `set(_relay_cache) == {"v"}` —— 而夹具在每个用例开头把缓存整个换掉，
     所以改模块级字面量对它完全不可见，变异实测不红。**属性在函数的写入点上，
     判据就必须打在写入点**（改用 AST 数 `_relay_cache[...] = ...` 的赋值次数后，
     同一个变异立刻变红）。
- ★★ **空守卫第九、十种形态（2026-09-10 下午各抓一个，仍是我自己写的）**：
  ⑨ **参数被重复的同名 query 静默吃掉**。UI 闸的 `usage_q()` 里 URL 已硬编码了
     `relay=relay`，我在 `extra` 里再传 `relay=sparse` 想换夹具 —— `URLSearchParams.get`
     取的是**第一个**值，稀疏夹具**根本没生效**，跑的还是稠密那份。
     而"轴上 7 个日期"这条断言在两份夹具下**都绿**，所以看不出来。
     判据：换夹具走**形参**（`usage_q(..., mode="sparse")`），别靠 query 覆盖 query。
  ⑩ **判据档位挑错，被上游的另一条 early-return 兜住了**。验"上一窗口必须整段可观测"
     时我挑了 30d 档 —— 它显示「—」不假，但那是 `mk()` 里 `if (!before) return null`
     （上期一条数据都没有）挡的，**根本没走到**被测的那条守卫；删掉守卫照样绿。
     真正的分界档是 **14d**（上期 14~27 天前里只有「23 天前」一天被观测过，部分重叠）。
     判据：变异验证时先问**这条断言的绿是谁给的** —— 多条 early-return 串在一条路径上时，
     必须挑一个只有被测那条能挡住的输入。
  ⑪ **闸只覆盖了不变量的一个方向**（2026-09-12）。「计费标记按行不按桶」这条，我只写了
     「**往后**：窗口走完之后的新行不继承标记」，而按桶标记的真实危害在**往回**那一侧
     —— 标记的那一刻把桶里闲置期的旧行一起标掉，一串**确实在漂**的窗口集体自称已锚定。
     新行是标记之后才建的，当然标不到它，所以「按桶标记」这个变异**照样绿**。
     判据：一条不变量若能从两侧被破坏（早/晚、多/少、往前/往回），闸就得有两条断言；
     **只有一条时，它在没覆盖的那一向上等于不存在**。变异也要照着两侧各打一个。
  ⑫ **断言撞上了解释这条规则的注释**（2026-09-13，一轮里踩了**五次**）。本仓注释密度极高，
     而注释里恰好就写着闸要找的那些词：`execv`（那行正说"为什么不用 execv"）、
     `state.json`（"为什么不写它"）、`data-cards-grid`（"这个属性是干什么的"）、
     `只读` / `不在轮换池`（"三态别合并"）、`新鲜`（几百行外的另一段说明）。
     症状分两种，**都不会指向真因**：`assertNotIn` 变**假红**，`index()` 取到注释那一处
     让窗口整个偏掉。判据：断言要打在**代码形态**上而不是词上 ——
     `os.execv(`、`}}>只读</span>`、`<div data-cards-grid`、只看 AST 里非 docstring 的字面量，
     或者干脆改成**行为闸**。⚠️ 一条会假红的闸，用户学会的是忽略它。
- ★★★ **一个变异变红，只证明它撞上的那一条断言是活的 —— 同一个测试里的其它断言仍可能是空的。**
  （2026-09-10 四方评审抓到，三个面板独立指出，我自己复现确认。）
  我给两条新闸各打了一个变异、都红了，于是报告「已变异验证」。评审换了**另一个方向**打：
  · VS Code 那条：我的变异是把 `VS Code` **插进**生效侧（撞上 `assertLess` 的顺序判断）⇒ 红；
    评审把用户可见的整句 `<b>不生效：VS Code</b>` **删掉** ⇒ **全绿**。原因是
    `re.search("生效范围：(.*?)</div>")` 把 **JSX 注释** `{/* …不生效…VS Code… */}` 也捕进去了，
    两个关键词全落在注释里 —— 形态④（断言打在自己的说明文字上）又犯一次。
  · `route_corrupt` 那条：我的变异是换回 `exit 78`（撞上 `assertNotIn`）⇒ 红；
    评审把 detail 的**后果整句抹掉** ⇒ **全绿**。因为 `PY[...][:600]` 那个窗口越过 detail
    读到了下一行 `# ★ …账号池那份` 注释，`"账号池" in body` 永远成立。
  · 顺带:`denylist` 那条的**主正则写成 `argv[i]`、源码是 `argv[$i]`，一次都没命中过**，
    整条闸挂在兜底正则上，而它把「agents 是第一个候选」写死 ⇒ 保留 `app-server` 只换顺序就**假红**。
  ★ 判据升级：**每一条 assert 都要有属于它自己的变异**，且变异方向要包含「把被断言的东西
    整个删掉」——只做「改成错的」会漏掉「根本不存在也通过」。
  ★ 断言前先剥掉**所有**形式的注释:python `#`、docstring、**JSX `{/* */}`**、shell `#`。
  ★ 定长切片（`[:600]`）取上下文是危险的:它会滑进下一段代码/注释。要么解析结构（AST/正则到边界），
    要么**直接调用函数拿返回值**——`route_corrupt` 那条改成真写一份坏路由再调 `route_status()` 之后，
    两个方向的变异都立刻变红。
- ★★★ **"改完了" ≠ "有人喂它"。** 同一轮评审的 critical：`proxy.py` 认了 `CODEX_ROTATE_STORE`，
  而 `install-launchd.sh` / `install-windows.ps1` 里**四个任务一个都没带这个变量**，
  Rust 侧 `spawn_cmd` 虽然设了但 `grep proxy.py lib.rs` **零命中**（app 根本不 spawn 代理）。
  本机看不出来:`deploy.sh` 把仓库路径烧进 `CODEXBAR_STORE_DEFAULT`，于是 app 与服务碰巧同一个目录；
  CI 出的安装包没有那个烧录值 ⇒ 分叉。**而我写的闸自己往 subprocess 里注入变量**，
  所以它证明的是"给了变量时两处算得一样"，永远证不到"服务定义供给了变量"。
  ★ 判据：**改了"谁来读"，就必须同时验"谁来写"**。配置项的闸要落在**产物**上
  （生成出来的 plist / task XML），不是落在读取方。见 `tests/test_installers_pass_the_store.py`
  ——它真的跑一遍安装脚本（`launchctl` 打桩、`HOME` 指向临时目录）再读 plist。
- ★★ **`launchctl bootout` 是异步的**，返回时任务常常还在 domain 里，紧跟的 `bootstrap` 撞
  `Bootstrap failed: 5: Input/output error`。配合 `set -e`，脚本会**停在那一行** ——
  该服务已 bootout、未 bootstrap，**就那么停着**，后面的任务连 plist 都没重写。
  2026-09-10 实测踩到（quotad 停了）。`emit` 现在轮询等它真的消失 + 重试 + **按"是否真的加载上"判**，
  不看 bootstrap 的退出码。
- ★★ **变异要确认打在了被测的那一处**（2026-09-10 实测）。用
  `s.replace(anchor, mutant, 1)` 打变异时，`1` 命中的是**第一处**匹配 ——
  `relay/monitor.py` 里 `if not isinstance(raw, dict):` 有两处（`day_models` 与 `fetch`），
  脚本改了前者、跑测试全绿，于是「闸是空的」这个结论本身是假的。
  判据：变异后先 `grep -n` 确认行号落在被测函数的范围内，或直接按行号改。
  这与本节已记的「替换没匹配 ＝ 假『已改好』」是同一族，只是它**匹配到了，但匹配错了地方**。
- ★★ **变异测试的前提是基线先绿**。测试本身已经红时，**任何变异都会"变红"**，绿灯全是假的。
