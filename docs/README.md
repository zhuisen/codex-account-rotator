## 这个仓库的文档分两层

**公开层**（在版本控制里）：`README.md` · `CHANGELOG.md` · `docs/`。
面向使用者：装什么、怎么用、出了问题怎么办、改过什么。

**内部层**（`.gitignore`，只在作者机器上）：`CLAUDE.md`（正本）· `AGENTS.md`（Codex 适配器）·
`memory.md`（进行时工作板）· `RUNBOOK.md` · `SETUP.md`。
面向维护：不变量、踩过的坑、未决事项。仓库转公开时它们**已从全历史移除**。

> 所以在公开仓库里看到「某处引用了 CLAUDE.md §8」这类交叉引用是正常的 ——
> 那份文件不在这里。关键结论会被搬进 `CHANGELOG.md` 的 BUG 条目，那是公开的。

## 写文档的三条规矩

1. **一个事实只有一个家。** 规范进 `CLAUDE.md`，历史进 `CHANGELOG.md`，进行时进 `memory.md`，
   使用说明进 `docs/`。同一件事写两处，迟早只改一处。
2. **陈述性的谎言比没有文档更糟。** 改了行为就把旧的那句**替换掉**，不要在后面追加一句
   「注：现已改为…」——读者会先读到旧的那句并据此行动。
3. **结论要带证据和日期。** 「实测 2026-09-07，4179 个会话里最近 50 个 76% 是 rotateproxy」
   这样的句子三个月后还能被检验；「比例很高」不能。
   ★ 本仓真栽过：一段注释里的实测比例（89:1）过期三个月没人复核，
   后来的人（包括 AI）把它当成现状反复引用 —— 详见 `CHANGELOG.md` 的 **B36**。
